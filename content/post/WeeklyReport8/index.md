## 笔记
### 应用工具
1.Burpsuite(攻击Web程序的集成应用框架)
 功能：
 Proxy:拦截http/https的代理服务器，拦截、查看、修改原始数据流
 Intruder:高度可自定，对Web应用程序进行自动化攻击
 Repeater:手动重放http请求，分析应用程序响应 
 Sequencer:分析不可预知的程绘画令牌和重要数据项随机性的工具
 Decoder:智能解码编码
 Comparer:通过相关请求和响应得到两项数据的可视化差异
2.curl(抓取网页、网络监控等，解决开发调试遇到的问题)
3.postman(网页调试工具，可视化版本curl)

# Web安全漏洞
  因为刚开始学习，并且我学的那个视频的原因，我第一个接触的漏洞是文件上传漏洞。对于这个漏洞的了解，于我个人的思路来看，大概就是在文件上传时有一定的缺陷，无法阻挡有害的内容（在表面即可看出有害，或是将有害内容一层层塞到文件之下的内容）进行上传到服务器系统，然后通过执行文件导致系统出问题的一种漏洞。这类型的漏洞主要是无法避免一些隐藏的绕过方式，例如后缀名绕过，前端验证这类低级的，还有htaccess，截断绕过这些较高级的。我也大概了解了通过自主代码审计（进入服务器系统中去观察内部文件代码）以及fuzz自动化审计来寻找合适、或是说可行的攻击方式来利用服务器的文件上传漏洞。
## 笔记
### 文件上传漏洞
#### 定义和原理
开发者开发功能时没有做足充分验证（包括前后端），允许用户上传各类恶意文件 关键：绕过

(docker的使用：
docker pull 容器地址------下载容器
docker run -d -p 端口映射 容器地址------启动容器
进入------https://本地端口/install.php)


### 绕过
1.文件后缀名绕过：文件名后添加数字(例如php3、php4等等)，若网页有对应的正则表达式能够解析这一类的文件，则可以触发
2.前端验证绕过：
   1-通过Burpsuite抓包，修改内容后放行
   2-通过Chrome禁止/删除js代码
3..htaccess绕过：
  1-htaccess：（分布配置文件）提供一种使得配置文件随文件夹的不同而不同的方式
  2-场景：启用了.htacccess文件的网站，使用此文件类型来绕过限制较全面的黑名单过来、
4.大小写绕过：将后缀名大小写更改（例如.php-->.pHp）
5.Windows文件流特性绕过：NTFS文件系统支持“多文件流”特性，一个文件可以包含多个数据流
6.%00截断绕过：对于白名单使用的绕过方式
  1-设置save_path=../upload/a.php%00
  2-上传一个内容为一句话木马的白名单类型文件
7.文件头检测绕过：将木马内容写入白名单类型中
#### 补充
3.上述的.htaccess绕过补充：
  1-上传一个.htaccess文件，内容为[AddType application/x-httpd-hph .test]
  2-上传木马文件，文件名为shell.text
  3-在浏览器中执行shell.text即可执行一次木马
4.上述大小写绕过补充：
  Windows对大小写后缀不敏感，当Linux对其敏感
6.截断绕过的补充：
  使用Burpsuite中断请求，再对文件需要截断的位置加上十六进制为00的截断符


### 下属笔记
1.php一句话木马：<?php @eval($_POST['cmd']); ?>
2.其他一句话木马的类型：ASP/ASPX/JSP/Python等
3.服务器关联性漏洞：IIS 5.x/6.0版本的解析漏洞
  (1)创建.asp文件目录时，服务器都解析为.asp文件
    www.xxx.com/xx/asp/xx.jpg会解析为asp文件
  (2)服务器不解析“;”以后的内容
    www.xxx.com/xx/asp;.jpg会解析为asp文件
4.Nginx解析漏洞：低版本Nginx中由PHP-CGI导致的文件解析漏洞（当URL中有不存在的文件时，PHP会向前解析）
  访问222.xx.com/phpinfo.jpg/1.jpg(1.jpg不存在)
  解析phpinfo.jpg文件，以php的形式
5.Apache解析漏洞：在1.x/2.x版本中，Apache会自右向左判断后缀，跳过不可识别后缀，直到遇到可识别后缀
  shell.php.test(test不可识别，php可识别，按php来解析)
6.源码审计：进入服务器系统内，可以详细了解Webapp的源码，以进行攻击方式的选择
7.Fuzz（模糊测试，自动化）：通过自动化的大量测试（或许类似于暴力破解？）主动去寻找可以用于渗透攻击的方式
